# Sticky Buttons

Возвращает поведение старых версий Minecraft: если зажать кнопку мыши, нажать
**F3 + T** (перезагрузка ресурсов) и отпустить мышь, кнопка остаётся зажатой —
игра продолжает копать / ставить блоки сама, как автокликер.

В 26.x это перестало работать. Мод возвращает эффект осознанно и предсказуемо:
залипание снимается повторным нажатием той же кнопки.

## Почему это перестало работать

Проверено по байткоду `MouseHandler` в 26.2 и 26.3:

1. `MouseHandler.onButton` обновляет `isLeftPressed` / `isRightPressed` только
   если **нет ни экрана, ни оверлея**:
   ```
   if (gui.screen() != null || gui.overlay() != null) → состояние кнопок не меняется
   ```
   На время перезагрузки ресурсов игра ставит `LoadingOverlay`, поэтому
   отпускание кнопки до состояния не доходит.

2. При закрытии оверлея `MouseHandler.grabMouse()` вызывает
   `KeyMapping.setAll()`, который заново читает физическое состояние клавиш через
   `InputConstants.isKeyDown`. То есть состояние привязок пересинхронизируется с
   реальным — «залипание» обнуляется.

Раньше пересинхронизации не было, и потерянное отпускание давало автоклик.
Патчить игру ради этого не нужно — эффект воспроизводится на уровне мода.

## Что делает мод

**Триггер — только F3+T**, не любая перезагрузка ресурсов. Перезагрузка из меню
настроек кнопки не зажимает.

1. Нажатие F3+T ловит `DebugKeysMixin` на `KeyboardHandler.handleDebugKeys` —
   там же, где игра проверяет `keyDebugReloadResourcePacks`. Состояние кнопок
   читается **до** перезагрузки: она занимает несколько секунд, за которые
   игрок успевает отпустить мышь.
2. Состояние берётся из устройства: SDL в 26.3, GLFW в 26.2 (через рефлексию,
   чтобы один код собирался под обе — в 26.2 нет `org.lwjgl.sdl`). Не из
   `MouseHandler`: тот обновляет флаги только при доставке события конкретной
   кнопки, поэтому «ЛКМ и ПКМ зажаты одновременно» через него определялось
   неполно — из-за этого раньше залипала только одна кнопка.
3. Каждый тик привязки `keyAttack` / `keyUse` / `keyPickItem` удерживаются через
   `StickyHolder`, а миксин на `KeyMapping.setDown(boolean)` не даёт игре их
   погасить. События мыши приходят **вне тика**, и без этого игра успевала
   сбросить флаг между установкой и опросом в `handleKeybinds`.
4. Повторное нажатие той же кнопки снимает залипание — дальше клик работает
   как обычно. При выходе из мира состояние сбрасывается.

Исключения: если открыт экран (инвентарь, Esc), отпускание проходит штатно и
залипание снимается — иначе игрок продолжал бы копать с открытым меню.

### Совместимость с Remove Reloading Screen

Мод не опирается на появление `LoadingOverlay`, поэтому работает и с `rrls`,
который этот экран убирает. Раньше детект шёл по оверлею — с `rrls` мод
не срабатывал вовсе.

На экране появляется подсказка: «Кнопка залипла — нажмите её снова, чтобы
отпустить».

## Сборка

```bash
./gradlew build -Pmc=26.3     # → build/26.3/libs/sticky-buttons-1.0.3+26.3.jar
./gradlew build -Pmc=26.2     # → build/26.2/libs/sticky-buttons-1.0.3+26.2.jar
```

Нужен JDK 25. Версии игры и Fabric API — в `targets/<версия>.properties`.

## Проверка

```bash
verify/run.sh 26.3
```

Стенды загружают **собранный jar** через classpath клиента:

- `VerifyMixinTarget` — цель миксина существует в этой версии игры
  (`KeyMapping.setDown(boolean)`), конфиг миксинов и аннотация на месте, поля
  `keyAttack` / `keyUse` / `keyPickItem` не переименованы. Без этого мод молча
  перестал бы работать при смене версии;
- `VerifySticky` — 30 проверок логики: ЛКМ и ПКМ **вместе**, ПКМ + средняя,
  все три, снятие по одной кнопке, две F3+T подряд, сброс при выходе,
  «перезагрузка из меню не зажимает» и «залипание держится 100 тиков».

Итого 50 проверок на каждую версию игры.

## Установка

1. Fabric Loader 0.19.5+ и Fabric API соответствующей версии.
2. Положить jar для своей версии игры в `mods/`.
3. Мод клиентский — на сервер его ставить не нужно.
